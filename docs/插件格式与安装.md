# 插件格式与安装

回答三个问题：`.zpx` 到底是什么、宿主装它的时候会检查什么、装完落在哪儿。

---

## 1. `.zpx` 就是 zip

`.zpx` 是**扩展名不同的 zip 压缩包**，宿主按 zip 解析。硬性要求只有一条：

> 压缩包**根目录**必须有 `plugin.json`。

也就是打包 `my-plugin/` 目录时要打**目录里的内容**，不要多套一层：

```text
✅ 正确                      ❌ 错误（多了一层）
plugin.json                  my-plugin/plugin.json
index.html                   my-plugin/index.html
vendor/ztools-sdk/…          my-plugin/vendor/ztools-sdk/…
```

压缩方式不限（stored 或 deflate 都能装）。本仓库的 `scripts/lib/zip.mjs`
只写 **stored** 条目，好处是零依赖、任何 zip 工具都能解开、也方便脚本直接读回
`plugin.json` 做校验。

---

## 2. 安装时宿主会检查什么

解包前逐条目校验，任一条不过就整体拒绝安装：

| 检查项 | 规则 | 失败时的提示 |
| --- | --- | --- |
| 路径越界 | 条目名不得是绝对路径、不得含 `..` | `.zpx` 含有越界条目 |
| 符号链接 | 带 `S_IFLNK` 属性位的条目一律拒绝 | `.zpx` 含符号链接 |
| 条目数量 | ≤ **4096** 个 | 超过上限 |
| 单条目体积 | ≤ **64 MiB** | 超过上限 |
| 总体积 | ≤ **256 MiB** | 超过上限 |

解包后再校验清单（`plugin.json`）：

| 检查项 | 规则 |
| --- | --- |
| `schema` | 必须为 `2`（v1 包会被明确拒绝） |
| `id` | 反域名、小写字母/数字/中划线、≤100 字符 |
| `version` | `major.minor.patch`（可带 `-pre` / `+build`） |
| `runtime.type` | 只能是 `webview` |
| `runtime.entry` / `logo` / `features[].icon` | 安全相对路径（非绝对、无 `..`、无空段） |
| `permissions[]` | 每项都必须是已知权限点 |
| `features[].code` | 非空且插件内唯一 |
| `features[].label` | 非空 |
| `cmds[].type` | 只能是 `over` / `files` / `regex` |
| `cmds` 长度区间 | `minLength ≤ maxLength` |

打包前跑 `node scripts/verify.mjs` 可以在本地把上面这套规则过一遍，
不用等到装的时候才发现问题。

### 内置插件不能被覆盖

来源为 `builtin` 的插件随宿主安装包升级，不接受 `.zpx` 覆盖安装；
用同名 `.zpx` 去装会得到明确报错，而不是静默替换。

---

## 3. 两种安装方式

### 3.1 本地文件安装（任何构建都能用）

1. 打开 设置 → **已安装插件**；
2. 在输入框里填入 `.zpx` 的**绝对路径**；
3. 点「导入本地插件」。

对应宿主命令 `plugin_install(path)`，安装后插件 `source = local`。
同一个包重复安装等于"覆盖更新"，不会报错。

### 3.2 从市场安装

设置 → **插件市场**：列表来自市场的 `/plugins` 接口，装的时候走
`market_install_plugin(name, downloadUrl)` → 下载 `.zpx` → **复用本地安装的同一条链路**
（只是把来源标记成 `market`）。接口与自建方式见
[市场与发布.md](市场与发布.md)。

---

## 4. 装完之后：文件落在哪

所有路径都在**数据目录**下（默认 `%APPDATA%` 对应的应用数据目录，可用
`ZTOOLS_DATA_ROOT` 覆盖；设置 → 我的数据 里能看到实际路径）：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 插件代码 | `<数据目录>/plugins/<插件 id>/` | 解包后的全部文件 |
| 插件私有存储 | `<数据目录>/plugins/<插件 id>/data/storage.json` | `ztools.storage.*` 读写这里 |
| 插件缓存目录 | `<数据目录>/cache/<插件 id>/` | `ztools.files.cacheDir()`；可清理 |
| 插件注册表 | `<数据目录>/plugin-registry.json` | 记录 id / 版本 / 来源（`local` / `market` / `builtin`）/ 是否启用 |
| 授权记录 | `<数据目录>/plugin-permissions.json` | 宿主侧文件，插件读写不到 |
| 插件日志 | `<数据目录>/logs/plugins/` | 插件 stdout/stderr 落这里 |
| 市场下载临时包 | `<数据目录>/cache/market/` | 装完即删 |

因此：**卸载 = 删注册表记录 + 删 `plugins/<id>/`**；备份插件状态 = 备份
`plugins/<id>/data/`。

---

## 5. 更新与版本比较

- 宿主记住已安装版本；市场条目里的 `version` 与本地不同即标记"可更新"；
- 版本比较按语义化版本：先比 `major.minor.patch`，数字相同时**没有预发布号的更新**，
  都有预发布号时按段比较（数字段按数值、其余按字典序）；
- 覆盖安装会替换 `plugins/<id>/` 下的代码，但**不会**动 `data/`，
  所以插件升级不会丢用户数据（除非你的插件自己改了 `data/` 的结构，那要自己写迁移）。

---

## 6. 常见安装失败与定位

| 报错关键词 | 大概率原因 | 怎么查 |
| --- | --- | --- |
| `仅支持插件清单 schema 2` | 包是 v1 或 `schema` 写错 | 解包看 `plugin.json` |
| `插件目录缺少 plugin.json` | 打包时多套了一层目录 | 用 `scripts/lib/zip.mjs` 的 `listEntries` 打印条目名 |
| `id 必须是反域名` | 用了大写、下划线或单段名 | 改成 `com.example.xxx` |
| `entry 必须是相对路径` | 写了 `file://` 或绝对路径 | 改 `runtime.entry` |
| `未知权限` | `permissions` 里权限点拼错 | 对照《插件开发指南》§5 |
| `.zpx 含符号链接` | 打包工具把软链接原样打进去了 | 重新打包，别把软链接放进插件目录 |
| 装上了但搜不到 | `features` 的 `cmds` 没命中 | 见《插件开发指南》§4 |

排查时最有用的一招：**把 `.zpx` 改名为 `.zip` 直接解开看目录结构**——
它本来就是一个普通 zip。
