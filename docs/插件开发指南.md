# 插件开发指南

面向要写 ZTools-Tauri 插件的人。读完应该能独立产出一个可安装、可搜索、能调宿主能力的插件。

本文的字段与规则都对照宿主实现（校验在 `ztools-plugin::manifest`，安装校验在
`ztools-plugin::installer`，能力入口在 `plugin_host.rs`）。

---

## 1. 一个插件最少要有什么

```text
my-plugin/
  plugin.json     清单（唯一的必需文件）
  index.html      运行时入口页面（入口名在清单里指定）
  main.js         页面脚本
  vendor/ztools-sdk/   自带 SDK（见 §6）
```

`.zpx` 就是**把上面这个目录打成 zip**，`plugin.json` 必须在压缩包**根目录**。

放进**本仓库**（`plugins/my-plugin/`）时还建议补齐市场信息，CI 与市场详情页会用到：

| 文件 | 用途 |
| --- | --- |
| `README.md` | 市场详情页正文（必填，`verify.mjs` 会检查） |
| `CHANGELOG.md` | 版本记录；**最新一节**会成为市场的发布说明，也是版本历史的来源（必填） |
| `logo.png` | 插件图标；构建时内嵌成 base64 写进市场清单 |
| （根目录）`categories-mapping.json` | 把目录名加进合适的分类，否则市场里会缺分类归属 |

最小可用的 `plugin.json`：

```json
{
  "schema": 2,
  "id": "com.example.my-plugin",
  "version": "1.0.0",
  "title": "我的插件",
  "runtime": { "type": "webview", "entry": "index.html" }
}
```

## 2. `plugin.json` 字段速查

> **和参考项目（ZTools Electron 插件）的差别**：那边是 `schema: 1` + `preload.js`，
> 运行在 Electron 里；ZTools-Tauri 是 `schema: 2` + 页面走 `@ztools/sdk`，
> 安装包是 `.zpx`。字段名基本一致，迁移时主要改这三处：
> `schema` → `2`、去掉 `preload.js`、把 `window.ztools.*` 调用换成 `ztools.*`（SDK）。

| 字段 | 必填 | 规则（违反会在安装时被拒） |
| --- | --- | --- |
| `schema` | ✅ | 必须是 `2`。v1 插件不兼容，会给出明确报错 |
| `id` | ✅ | 反域名，至少两段，≤100 字符，每段 ≤63；只允许**小写字母 / 数字 / 中划线**，不能以 `-` 开头或结尾。例：`com.example.text-toolkit` |
| `version` | ✅ | 语义化版本 `major.minor.patch`，可带 `-pre` / `+build` |
| `name` | ➖ | 机器短名（可读），不填时展示名回退到 `title` → `id` |
| `title` | ➖ | 展示标题（面板/设置页/市场都显示它） |
| `author` / `description` | ➖ | 作者与一句话描述（市场列表会用到） |
| `logo` | ➖ | 图标，**相对插件根**的安全路径（如 `logo.png`），建议 ≥48×48 |
| `runtime` | ✅ | `{ "type": "webview", "entry": "index.html" }`；`type` 目前只支持 `webview` |
| `development` | ➖ | 开发态入口 `{ "entry": "http://127.0.0.1:15180" }`（可填 http(s) 或相对路径） |
| `permissions` | ➖ | 能力声明数组，取值见 §5，未声明的能力一律拒绝 |
| `features` | ➖ | 功能与搜索指令，见 §4 |

### 路径字段的"安全相对路径"是什么

`runtime.entry`、`logo`、`features[].icon` 都必须是**相对插件根**的路径：

- 不能是绝对路径（`C:\…`、`/etc/…`）；
- 不能含 `://`；
- 不能含 `..` 或空段（`a//b`）。

原因是插件装到 `<数据目录>/plugins/<id>/` 后，宿主只允许它引用自己目录内的文件，
否则一个插件就能借入口读到别的目录。

### 其他约定

- **未知字段会被忽略**（不会因此安装失败），所以可以放 `"$schema"` 之类的说明字段；
- `features[].code` 在插件内必须**唯一**；
- 一个插件可以声明多个 `features`，主面板会把它们分别搜出来。

## 3. 运行与生命周期

插件页面在宿主的主面板里加载，页面通过 SDK 订阅生命周期：

```js
import { bootstrap, ztools } from './vendor/ztools-sdk/index.js';

bootstrap({
  onEnter(event) {
    // 用户在主面板命中本插件的某个 feature，或插件窗口被再次唤起
    console.log(event.kind, event.code, event.payload);
  },
  onExit() {},
  onBackground() {},
  onDisable() {},
  onPluginDetach() {}
});
```

| 回调 | 触发时机 | 你能拿到什么 |
| --- | --- | --- |
| `onEnter` | 主面板命中 feature / 再次进入插件 | `event.code`（哪个 feature）、`event.payload`（载荷，见下） |
| `onExit` | 用户切换插件、面板关闭、调用 `ztools.exit()` | —— |
| `onBackground` / `onDisable` | 插件被切到后台 / 被禁用 | —— |
| `onPluginDetach` | 插件视图被"分离到独立窗口" | —— |

### `payload` 是什么

载荷由**触发它的 feature 指令类型**决定（宿主在 `search_execute` 时透传）：

| 指令类型 | `payload` |
| --- | --- |
| `over` / `regex` | 主面板输入框文本 |
| `files` | 拖入/选中的文件列表（含真实路径） |
| 其它 | `null` |

示例：`text-toolkit` 就是靠 `onEnter` 拿到输入文本并立刻执行对应操作。

### 页面能力

- 页面就是普通 HTML/JS，可以随意用 DOM、`fetch`（受 CSP 限制）与本地文件；
- 与宿主的一切交互都走 SDK（内部是 Tauri IPC），**不要**直接 import `@tauri-apps/api`；
- 主题令牌由宿主注入：用 `var(--bg-color)` / `var(--text-color)` / `var(--primary-color)`
  等变量就会自动跟随用户在设置里选的主题（见各示例的 `styles.css`）。

## 4. 让插件能被搜到：`features` 与 `cmds`

```json
{
  "features": [
    {
      "code": "text.upper",
      "label": "文本：转大写",
      "cmds": [{ "type": "over", "label": "转大写", "minLength": 1, "maxLength": 2000 }]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 功能码，插件内唯一；执行时宿主靠它找到这个 feature |
| `label` | 面板/搜索结果里显示的名称（**也参与拼音搜索**） |
| `icon` | 可选，相对插件根的图标路径 |
| `cmds[]` | 额外的匹配规则，命中后这个 feature 才会出现在结果里 |

`cmds[].type` 只有三种：

| 类型 | 出现条件 | 典型用法 |
| --- | --- | --- |
| `over` | 输入长度落在 `[minLength, maxLength]` **且** label 命中 | "选中文本 → 处理" |
| `files` | 拖入的文件路径匹配 `match` 正则（不填则只要拖了文件就出现） | "压缩这些文件" |
| `regex` | 输入文本匹配 `match`（支持 `/pattern/i` 与裸 `pattern`） | "输入看起来是链接 → 打开" |

> 注意：`over` 指令**必须** label 命中才会出现——这是为了避免"任意输入都命中一堆示例指令"
> 把搜索结果刷满。label 支持中文子串与拼音（全拼 / 首字母）。

## 5. 权限：声明了才能用

插件能调用的宿主能力受 `permissions` 约束。宿主把权限分成三档：

| 档位 | 行为 | 权限点 |
| --- | --- | --- |
| **Implicit**（默认允许） | 无需声明、无弹窗 | `storage.read`、`storage.write` |
| **OnDeclaration**（声明即放行） | 写进 `permissions` 即可用 | `dialog.open`、`network`、`shell.openExternal`、`notification.show`、`features.manage` |
| **Explicit**（需用户授权） | **首次调用**在主面板弹确认框：允许 / 本次允许 / 拒绝 / 永久拒绝 | `clipboard.read`、`clipboard.write`、`input.simulate`、`screen.capture`、`window.create`、`fs.read.any`、`fs.write.any` |

规则细节：

- **未声明 = 直接拒绝**（不会弹窗），错误 `permissionDenied`，`detail` 会告诉你缺哪个权限；
- 选「永久拒绝」后会记住（`<数据目录>/plugin-permissions.json`），下次静默拒绝；
- 授权记录是**宿主侧文件**，插件自己的 `storage` 读写不到，插件无法自我授权；
- 用户可在设置 → 插件里撤销授权；
- **声明了不等于随便用**：`fs.read.any` / `fs.write.any` 还额外受"用户经系统对话框授权过的
  路径范围"约束（见 §7）。

写代码时请把能力调用包起来，被拒时给出可读提示而不是白屏：

```js
try {
  await ztools.clipboard.writeText(text);
} catch (error) {
  // error.kind === 'permissionDenied' 时提示用户去授权
}
```

## 6. SDK：插件必须自带

插件**不能**假设宿主提供 SDK 文件，也不能直接依赖 `@tauri-apps/api`：
发布时把 SDK 放进插件的 `vendor/ztools-sdk/`，用相对路径 import：

```js
import { bootstrap, ztools, ZToolsApiError } from './vendor/ztools-sdk/index.js';
```

本仓库用 `node scripts/sync-sdk.mjs` 同步（来源是 ZTools-Tauri 的
`packages/ztools-sdk/dist`，可用 `--sdk <目录>` 或 `ZTOOLS_SDK_DIST` 覆盖）。

### 能力总表

| 命名空间 | 方法 | 需要的权限 |
| --- | --- | --- |
| `ztools.clipboard` | `readText` `writeText` `readFiles` `writeFiles` `writeImage` `history` `pasteHistory` `removeHistory` `clearHistory` `historyImage` `status` | `clipboard.read` / `clipboard.write` |
| `ztools.storage` | `get` `set` `remove` `list` `clear` | 默认允许 |
| `ztools.dialog` | `openFile` `saveFile` `showMessage` | `dialog.open` |
| `ztools.ui` | `showNotification`(`toast`) `setSubInput` `removeSubInput` `setSubInputValue` `subInputFocus` `subInputSelect` `subInputBlur` `onSubInputChange` `setHeight` `detach` `devtools` | 通知需 `notification.show` |
| `ztools.shell` | `openExternal` `openPath` `showItemInFolder` `trash` `beep` | `shell.openExternal` |
| `ztools.http` | `request` | `network` |
| `ztools.fs` | `readText` `writeText` `list` | `fs.read.any` / `fs.write.any` |
| `ztools.input` | `key` `type` `mouse` | `input.simulate` |
| `ztools.screen` | `capture` `fetch` `save` | `screen.capture` |
| `ztools.window` | `open` `close` | `window.create` |
| `ztools.files` | `getPathForFile` `cacheDir` | —— |
| `ztools.features` | `list` `set` `remove` | `features.manage` |
| `ztools.events` | `on` | —— |
| `ztools` | `exit()` | —— |

顶层还导出 `onEnter` / `onExit` / `onBackground` / `onDisable` / `onPluginDetach`
（单独注册）与 `bootstrap({...})`（一次注册多个）。

> 能力的具体入参与返回见 SDK 的 TypeScript 定义
> （`vendor/ztools-sdk/index.d.ts`）——那是权威签名。

## 7. 文件访问的两个前提

`ztools.fs.*` 要同时满足：

1. 清单里声明 `fs.read.any` / `fs.write.any`，且用户已授权（Explicit 档）；
2. **路径在用户授权过的范围内**——范围来自系统对话框的选择：
   `ztools.dialog.openFile()` / `saveFile()` 返回的路径会被宿主记入本插件的可访问范围。

另外，插件对自己 `<数据目录>/cache/<插件 id>/` 的读写是预置允许的，
适合放临时文件与导出中间产物。

```js
const file = await ztools.dialog.saveFile({ defaultPath: 'notes.md' });
if (file) await ztools.fs.writeText(file, '内容'); // 这个路径此后对本插件可读写
```

## 8. 调试

1. **开发态指向本地服务**：在 `plugin.json` 里写
   `"development": { "entry": "http://127.0.0.1:15180" }`，宿主会从你的 dev server 加载
   页面（改代码刷新即可，不必重新打包灌装）；
2. **打开 devtools**：插件里调 `ztools.devtools()`（开发模式可用）；
3. **看日志**：宿主把插件 stdout/stderr 落到插件日志里，异常会带插件 id；
4. **验证一遍再打包**：`node scripts/verify.mjs`（清单规则、包结构、市场一致性）。

> 提醒：`development.entry` 只影响开发态；正式安装（`.zpx`）永远用 `runtime.entry`。

## 9. 打包与发布

```bash
node scripts/sync-sdk.mjs                        # 确保 vendor/ 是最新 SDK
# 只打一个插件（调试用）：
node scripts/pack.mjs plugins/my-plugin out/my-plugin-1.0.0.zpx
# 按仓库流程打包 + 生成市场清单：
node scripts/build-plugins.mjs --plugin my-plugin
node scripts/generate-plugins-json.mjs
node scripts/verify.mjs
```

正式发布走 PR：合并到 `main` 后 CI 会自动检测变动插件、打包 `.zpx` 并创建 Release
（流程与产物见 [市场与发布.md](市场与发布.md)）。**发新版本必须递增 `version`**，
否则合并逻辑会认为版本没变、继续沿用旧包。

发布前自查：

- [ ] `id` 是反域名且**全局唯一**（市场用它当主键）；
- [ ] `version` 已递增（宿主按版本判断"可更新"）；
- [ ] `README.md` 写清功能与权限用途（会显示在市场详情里），`CHANGELOG.md` 顶部加了本次版本一节；
- [ ] `node scripts/verify.mjs` 通过；
- [ ] 在真机上装一次并跑通主流程（含权限弹窗的允许与拒绝两条路径）。

## 10. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装报"仅支持 schema 2" | 清单还是 v1 | 把 `schema` 改为 2 并按本文补字段 |
| 安装报"entry 必须是相对路径" | 入口写了绝对路径或 URL | `runtime.entry` 用 `index.html` 这类相对路径；远程地址放 `development.entry` |
| 安装报"未知权限" | `permissions` 里写了不存在的权限点 | 对照 §5 的表 |
| 面板里搜不到插件 | feature 的 `cmds` 没命中（`over` 必须 label 命中） | 检查 `label`/`minLength`/`maxLength`，或直接输入 feature 的 `label` |
| 能力调用报 `permissionDenied` | 没声明，或 Explicit 权限没被授权 | 补齐 `permissions`，并在弹窗里允许 |
| 插件页面白屏 | `runtime.entry` 指向的文件不在包里 / 路径大小写不符 | 解包 `.zpx` 或跑 `verify.mjs` 检查 |
| 图标不显示 | `logo` 路径不对，或清单里没写 | 插件内按相对路径引用；构建时 `logo` 会被内嵌成 base64 写进市场清单 |
